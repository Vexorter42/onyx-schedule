# Onyx

Android-приложение с расписанием занятий Российского университета кооперации.

Показывает пары любой группы любого филиала. Филиал, год набора и группа
выбираются один раз, после чего расписание открывается сразу при запуске —
в том числе без интернета.

## Что умеет

- **Профиль.** Филиал → год набора → группа выбираются один раз и сохраняются
  (DataStore). При следующем запуске приложение открывается сразу на расписании.
- **Офлайн.** Каждая загруженная неделя целиком лежит в локальной базе (Room).
  Экран всегда рисуется из базы, сеть только дописывает туда свежие данные,
  поэтому при отсутствии интернета расписание показывается как обычно —
  с пометкой «Нет сети. Данные от …».
- **Предзагрузка.** Вместе с текущей неделей тихо подтягиваются соседние,
  так что листание вперёд/назад работает мгновенно и офлайн.
- **Всегда актуально.** Расписание перезапрашивается при каждом открытии приложения
  и раз в час в фоне.
- **Навигация по неделям**, кнопка возврата к текущей неделе, pull-to-refresh.
- **Полоска дней недели** сверху: точка отмечает дни с парами, тап прокручивает
  к нужному дню. При открытии текущей недели список сразу встаёт на сегодня.
- **Идущая пара видна сразу** — её карточка обведена, в углу «ещё N мин»,
  а цветная полоска слева работает шкалой: заполняется сверху вниз ровно на столько,
  сколько от пары уже прошло.
- **Тёмная тема по умолчанию** (переключается на светлую или системную в настройках).
- **Смена группы/филиала** в настройках, шапка с иконкой и версией.
- **Поделиться неделей** — текстом в чат группы.
- **Время филиала.** Пары заданы в местном времени филиала, а не телефона:
  «идёт сейчас», полоска прогресса и напоминания считаются в поясе филиала,
  иначе у заочника из другого региона всё уезжало бы на разницу часов.
- **Скрытый раздел «Веселье»** — девять нажатий на иконку в настройках.
  Внутри выбор акцентного цвета и статистика недели.
- **Обновления.** При запуске приложение сверяется с релизами на GitHub. Если вышла
  новая версия, в шапке появляется кнопка с пульсирующей точкой: по нажатию
  открывается список изменений и кнопка «Обновить» — APK скачивается сам
  и передаётся системному установщику.
- **Уведомления** — четыре независимых типа, каждый отключается отдельно:
  утренняя сводка на день, вечерний обзор на завтра, напоминание за 5/10/15/30 минут
  до каждой пары и сообщение об изменениях в расписании. Есть кнопка «Проверить
  уведомление» — сразу видно, не режет ли их система.

## Сборка

Требуется JDK 17+ (подойдёт тот, что идёт с Android Studio) и Android SDK 36.

```bash
./gradlew assembleDebug
```

APK появится в `app/build/outputs/apk/debug/app-debug.apk`.
Релизная сборка (`assembleRelease`) проходит через R8 и весит ~1,5 МБ.

> **Важно:** путь к проекту не должен содержать кириллицу или другие не-ASCII
> символы — Android Gradle Plugin такую сборку отклоняет.

## API

Приложение обращается напрямую к JSON API, на котором работает
[new-schedule.ruc.su](https://new-schedule.ruc.su) (без ключей и авторизации).

Базовый адрес: `https://api-schedule.ruc.su/api/v1`

| Метод | Назначение |
|---|---|
| `GET /get_branches` | Список филиалов: `[{guid, code, name}]` |
| `GET /get_years` | Годы набора: `[{guid, code, name}]` |
| `GET /get_groups_filter/{branchGuid}/{yearGuid}` | Группы, сгруппированные по направлениям: `[{name, groups: [{guid, name, owner}], single_element}]` |
| `GET /get_employees/{branchGuid}` | Преподаватели: `[{GUID, Name, Male, Position}]` — сейчас не используется |
| `GET /get_schedule/group/{branchGuid}/{groupGuid}/{date}` | Расписание на неделю |

`{date}` — либо `no` (текущая неделя), либо дата в формате `yyyy.MM.dd`;
сервер возвращает неделю (пн–вс по ISO-8601), в которую эта дата попадает.

Ответ `get_schedule`:

```json
{
  "schedule": {
    "01.09.2026 - Вторник": [
      {
        "Data": "01.09.2026", "DayOFWeek": "2",
        "Time": "4", "Time_start": "14:00", "Time_end": "15:30",
        "Group": "МДК(МДК)1-О/Бп/ГВ25", "SubGroup": "",
        "Type": "Лекция", "Discipline": "Теория принятия решений",
        "Employee": "Брилон Андрей Валериевич", "Classroom": "1-306"
      }
    ]
  },
  "date": { "back": "2026.08.25", "next": "2026.09.08", "monday": 31, "sunday": 6 }
}
```

На пустой неделе `schedule` приходит как `{}` — десериализатор
`ScheduleMapSerializer` терпит и пустой массив на случай изменений на бэкенде.

**Доступ только из России.** Сайт стоит за DDoS-Guard и отвечает `451` тем, кто
пришёл не с российского адреса. Обойти это на стороне клиента нельзя — блокировка
серверная. Приложение распознаёт `451` отдельно от сетевых ошибок и честно пишет,
что нужен российский IP, а не «нет интернета». Уже загруженные недели при этом
продолжают открываться офлайн.

## Архитектура

Один модуль, ручной DI (`AppContainer`), MVVM + однонаправленный поток данных.

```
data/
  remote/   Dto.kt, ScheduleApi.kt (OkHttp + kotlinx.serialization), NetworkModule.kt
  local/    Entities.kt, Daos.kt, AppDatabase.kt (Room)
  prefs/    UserPrefs.kt (DataStore: профиль + тема)
  repo/     CatalogRepository.kt, ScheduleRepository.kt, SyncRunner.kt
domain/     Model.kt (Branch, Year, Group, Lesson, WeekSchedule, Profile), SyncResult.kt
ui/
  setup/    выбор филиала / года / группы
  schedule/ главный экран недели
  settings/ профиль, тема, очистка кэша
  theme/, common/
notifications/
  Notifier.kt            каналы и построение уведомлений
  AlarmScheduler.kt      планирование будильников (пары, утро, вечер)
  AlarmReceiver.kt       показывает уведомление и перепланирует следующие
  BootReceiver.kt        восстановление будильников после перезагрузки
  ScheduleCheckWorker.kt WorkManager: ежедневная сверка расписания
util/       WeekUtils.kt (границы недели, русские даты), NetworkMonitor.kt
```

**Уведомления.** Напоминания о парах — точные будильники `AlarmManager`
(`SCHEDULE_EXACT_ALARM`); если система их не разрешила, приложение честно
предупреждает и откатывается на неточные. Сводки — обычные неточные будильники.
Весь план пересобирается целиком при каждом поводе (запуск, срабатывание любого
будильника, смена настроек, перезагрузка) — это проще и надёжнее, чем править
отдельные будильники. Поиск изменений живёт в `ScheduleCheckWorker`: раз в сутки
он перекачивает текущую и следующую неделю и сравнивает пары по ключу
«дата + номер пары».

**Ключевое решение:** Room — единственный источник правды для UI.
`ScheduleRepository.observeWeek()` отдаёт `Flow` из базы; сеть вызывается отдельно
и только пишет в базу. Отсюда бесплатно получаются офлайн-режим, мгновенный
первый кадр и корректное поведение при потере связи.

Неделя идентифицируется ключом `"<guid группы>|<понедельник в ISO>"`.
Таблица `week_meta` отмечает, что неделя выкачана целиком: это позволяет
отличить «пар нет» от «ещё не загружали». Кэш автоматически чистится
за пределами окна −4 / +8 недель.

**Когда данные обновляются:**

- при каждом выходе приложения на передний план — текущая неделя
  перезапрашивается всегда, молча, без индикатора (данные из базы уже на экране);
- раз в час в фоне (`ScheduleCheckWorker`) — текущая и следующая недели,
  с проверкой изменений; система может сдвинуть запуск, если телефон в глубоком сне;
- при листании на другую неделю — если она не обновлялась больше часа;
- вручную — жестом pull-to-refresh.

## Известные ограничения

- Расписание преподавателей API отдаёт (`get_employees` + `get_schedule/employee/...`),
  но в приложении пока не реализовано — добавляется без изменения архитектуры.
- Виджета на рабочий стол нет.
- Обновления ставятся через `REQUEST_INSTALL_PACKAGES` — это нормально для
  приложения вне Play, но в Google Play такую сборку не примут.
- Библиотеки закреплены на версиях, совместимых с `compileSdk 36`; более свежие
  требуют AGP 9.1+ и `compileSdk 37`.
